# Безопасность

## Криптографические операции

Публичный Docker-образ не содержит КриптоПро или `pycades`. Каталог услуг, XSD-проверка и `/goskey/preview` доступны без них. Получение токена и `/goskey/submit` требуют отдельно лицензированного runtime и без него завершаются `503`; `/get_certificates` при этом возвращает пустой список, а выбрать отсутствующий сертификат нельзя.

| Операция | Инструмент | Примечание |
|---|---|---|
| Хранение закрытого ключа | Опциональный КриптоПро CSP, контейнер `xxx.000` | Монтируется в `/var/opt/cprocsp/keys/app/` только в signing runtime |
| Подпись `api_key` для ЕСИА | `pycades.Signer` + `CADESCOM_CADES_BES`, detached | base64 -> urlsafe base64 |
| Подписи архива Госключа | `epgu-api` manifest + `pycades`, detached | Отдельный `.sig` обязателен для `req.xml` и каждого документа |
| TSA | `TSAAddress` передаётся `pycades.Signer` | Код запрашивает тип `CADESCOM_CADES_BES`; наличие TSA не меняет заявленный тип подписи |
| Валидация XML | безопасный `lxml` parser + XSD профиля | Выполняется для `/push` и `/push/chunked`; Госключ генерируется typed-моделями |
| TLS к ЕПГУ | `httpx` + trust store runtime | Публичный образ не устанавливает ведомственные/ГОСТ CA автоматически |

## JWT (accessTkn ЕСИА)

- Получается в обмен на подпись API-key.
- Хранится в **глобальной переменной процесса** (`ACCESS_TKN_ESIA`).
- Используется как `Authorization: Bearer ...` для всех вызовов `svcdev_host`.
- Срок действия (`exp`) парсится без верификации подписи (`_decode_jwt_exp`) и возвращается клиенту вместе с токеном, а также доступен через `GET /version` (поле `runtime.access_tkn_exp`).
- На фронтенде декодируется только для отображения `exp` (никакой верификации - JWT подписывает ЕСИА).

## Угрозы и меры

| Угроза | Оценка | Меры |
|---|---|---|
| Утечка `KeyPin` через env | высокая | Использовать Docker secrets / Vault в prod |
| Утечка приватного ключа (volume) | высокая | Шифровать том, ограничить FS-права, не коммитить `xxx.000` |
| CSRF на backend | средняя | Все state-changing browser-запросы проходят server-side Origin/Referer allow-list; wildcard никогда не разрешает mutation. Для shared deployment всё равно нужен auth gateway/CSRF policy |
| MITM к ЕПГУ | низкая | Только HTTPS + корневой CA |
| Повторная подача/replay | средняя | ЕПГУ отвечает дедупликацией по orderId; на стороне системы - идемпотентные ключи |
| Отсутствие аудита | средняя | Логировать все операции подписания с указанием пользователя/ключа |
| XXE / entity expansion | низкая после мер | Используется `XMLParser(resolve_entities=False, no_network=True, huge_tree=False)`; не ослаблять эти параметры |
| Логирование PII | средняя | Не логировать тело заявления/PII в prod; маскировать |

## Реализовано в коде (2026-08)

-  Безопасный парсер XML: `XMLParser(resolve_entities=False, no_network=True, huge_tree=False)` в `validate_xml_content` (см. `app.py`).
-  Парсинг `exp` JWT: `_decode_jwt_exp` -> возвращается клиенту и через `/version`.
- CORS и server-side Origin/Referer guard через env `ALLOWED_ORIGINS`; CLI/SDK без browser origin поддерживаются, wildcard не разрешает browser mutations.
-  Разделение `certs/public/` (в git) и `certs/personal/` (gitignored).
-  Пути XML/XSD и имена ZIP проверяются на traversal; дубликаты имён отклоняются.
-  Reference-only профили блокируются до внешнего вызова; для detached-подписи проверяется наличие соответствующего `.sig`.

## Дальнейшие рекомендации

- Перенести глобальное состояние в защищённое хранилище (Redis с TTL на токен).
- Авто-обновление токена при приближении `exp` (сейчас обновление инициирует клиент).
- Аудит операций подписания (кто, когда, какой сертификат, хэш данных).
- `KeyPin` - через Docker secrets / Vault вместо env.

## Сертификаты CA

- Публичный backend-образ не добавляет `test_ca_rtk3.cer` и не поставляет ведомственные или ГОСТ-корни.
- Требуемую цепочку доверия для выбранного тестового/промышленного контура должен установить оператор лицензированного runtime; не копируйте случайные сертификаты из устаревших примеров.
- Все публичные CA должны лежать в `api-gosuslugi-backend/certs/public/` (видны в репозитории), личные ключи и сертификаты - в `certs/personal/` (gitignored).
