# Одна организация без приватных дополнений

Публичная установка самостоятельна. Приватные модули не нужны для справочного
гайда, карточки подключения, подготовки формы и воспроизводимого mock-цикла
ФССП 60010153 через HTTP API и MCP.

## Полный цикл одной командой

Нужен Python 3.12+ с модулем venv. Из корня репозитория, Windows PowerShell:

```powershell
$checkRoot = Join-Path $env:LOCALAPPDATA ('EPGU Public Check ' + [guid]::NewGuid().ToString('N'))
python project/examples/check_single_org.py --output "$checkRoot"
```

Linux/macOS:

```bash
python3 project/examples/check_single_org.py --output "$(mktemp -d)"
```

Скрипт создает отдельное виртуальное окружение и устанавливает зависимости
публичного backend и MCP. Интернет нужен pip для получения зависимостей.
Сам цикл не обращается к Госуслугам: ответы ЕПГУ предоставляет MockTransport.
Docker, приватный репозиторий, лицензия дополнения, КриптоПро, реальная
учетная запись и API-Key Госуслуг для этой проверки не нужны.

Для каждой цепочки HTTP и MCP выполняются подготовка формы, проверка XML/XSD,
предпросмотр и отдельное одобрение плана, резервирование, отправка ZIP,
конечный статус и получение mock-документа. Повтор execute не создает вторую
подачу. Временный ключ интеграции нашей установки отзывается, файл удаляется,
проверочный backend останавливается. В примере человека моделирует тестовый
сценарий; MCP не получает возможность одобрять планы.

Итог: `single-org-check.json`, подробная квитанция `cycle/receipt.json`,
синтетические XML в `cycle/http` и `cycle/mcp`. Каталог результата должен
быть пустым и находиться вне Git и вне данных существующей установки.

Если зависимости уже установлены, можно запустить непосредственно
[fssp_mock_cycle.py](../examples/fssp_mock_cycle.py) по
[подробной инструкции цикла](FSSP_MOCK_CYCLE.md).

## Границы публичной редакции

| Возможность | Публичная поставка |
| --- | --- |
| Гайд, схемы, ручной маршрут и карточка подключения | Без входа и приватных модулей |
| Подготовка форм и проверка контрактов | Публичный backend и SDK |
| Полный учебный цикл одной организации через HTTP/MCP | Явный mock-сценарий, описанный выше |
| Реальные запросы | Нужны доступ оператора к конкретной услуге, ключи и подходящий криптопровайдер |
| Организации и сотрудники одновременно, браузерная автоматизация | Расширения; не обязательны для этого mock-цикла |

Успешный mock не подтверждает выдачу допуска TEST/PROD. Демонстрационный
исполнитель не включается в штатный backend или MCP незаметно. Для реального
сервиса нужно отдельно настроить собственный контекст и пройти подключение.
Публичный backend рассчитан на одного доверенного оператора; этот пример не
превращает его в сервис с изоляцией разных пользователей и организаций.

## Запуск тестов на Windows

Ключи, включая синтетические ключи тестовых интеграций MCP, должны находиться
вне Git. Если Windows выбирает рабочую папку вместо системного временного
каталога, явно задайте отдельный `--basetemp`:

```powershell
$testTemp = Join-Path $env:LOCALAPPDATA ('EPGU Tests ' + [guid]::NewGuid().ToString('N'))
# Из project/api-gosuslugi-backend, после установки requirements-test.txt:
python -m pytest -q --basetemp "$testTemp"
```

Не обходите проверку расположения ключа и не указывайте каталог рабочей
установки для временных файлов тестов.
