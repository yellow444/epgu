# Аудит кода, контрактов и готовности к публикации - 12.08.2026

## Итог

Репозиторий приведён к модели fail-closed: наличие услуги в официальном каталоге больше не разрешает отправку с чужим XML. В версионируемом реестре 21 профиль; три профиля Госключа доступны, 18 справочных профилей видны во frontend, но блокируются backend.

Доказуемая локальная часть контракта существенно улучшена: базовая спецификация обновлена до v1.14, официальные файлы хэшированы, XML/XSD привязаны к услугам, chunked-отправка выполняется backend с корректными индексами/именами, а Госключ реализован общей типизированной Python-библиотекой. Это не является доказательством успешной промышленной интеграции: live-приёмка в тестовом контуре с реальными полномочиями и лицензированным ГОСТ-runtime в данный аудит не входила.

Публичная публикация всё ещё заблокирована секретами и проприетарным архивом в истории Git. Их нельзя исправить одним `.gitignore`; действия перечислены ниже.

## Объём и методика

Проверены backend, frontend, Python-пакет, тесты, скрипты, реестр услуг, локальные XML/XSD и официальные материалы. Структурный отчёт строится детерминированно скриптом [`scripts/audit_repository.py`](../scripts/audit_repository.py) и сохраняется в [`code_audit.json`](./code_audit.json).

Методика включает:

- AST-разбор Python: файлы, функции, методы, классы, присваивания, аннотации, docstring и тестовые функции;
- консервативный regex-инвентарь JavaScript; синтаксическими gate остаются Jest и production build;
- проверку структуры всех профилей, допустимых путей/placeholder, наличия рабочих шаблонов или генераторов и SHA-256 официальных источников;
- unit/contract/golden-тесты без сетевых вызовов в ЕПГУ;
- ручную сверку неоднозначностей спецификаций.

Статистика не доказывает семантическую корректность каждой переменной. В частности, число `variables` ниже - число AST-присваиваний, а не перечень независимых доменных полей; локальные переменные Python не обязаны иметь аннотацию. Корректность объектов и методов подтверждается типами, инвариантами, тестами и профильными схемами вместе, а не количеством комментариев.

## Исправленные классы рисков

- Удалена ложная модель, в которой несколько кодов услуг использовали один XML ФССП. Профиль теперь хранит собственные документы, XSD, transforms, режим, подпись, варианты, источник и хэши.
- Неверифицированный профиль доступен для просмотра, но не может получить рабочий XML или пройти `/push`/`push/chunked`.
- `SERVICES` применяется как безопасный deep merge и не может незаметно стереть вложенный submission-контракт.
- XML/XSD читаются только из ограниченного `XML_ROOT`; запрещены абсолютные пути, `..`, неизвестные placeholders и дубли имён.
- `submissionContext` сохраняется скалярно и согласованно подставляет `{orderId}`, `{guid}`, дату/время; UI-only поля не пересылаются upstream.
- Chunked-путь реально делит созданный ZIP, использует `.z001` для первой из нескольких частей, `chunk=0..n-1`, обязательный `meta` и проверку ответа/orderId.
- `region` проверяется как runtime ОКАТО, а не берётся из фиктивного значения профиля.
- Frontend выбирает услугу из backend-реестра, показывает официальный источник/статус/capability и не разрешает отправку заблокированного варианта.
- Python-клиент исправляет модели страниц/статусов, download/cancel/dictionary/error-контракты и предоставляет общий архиватор, подпись и типизированные модели Госключа.

## Поиск Python-аналога и сравнение с Go

При проверке GitHub/PyPI точного Python-аналога для API ЕПГУ/ГУСМЭВ не найдено. Пакет [`gosuslugi-api`](https://pypi.org/project/gosuslugi-api/) относится к ГИС ЖКХ и не является заменой.

[`ofstudio/go-api-epgu`](https://github.com/ofstudio/go-api-epgu) и его [API-документация](https://pkg.go.dev/github.com/ofstudio/go-api-epgu) использованы как поведенческий референс. Он полезен для последовательностей вызовов, но не является источником истины для текущих 21 профилей: формальный v1.14 и приложения услуг имеют приоритет. В ходе аудита Go-референса также отмечены повторяющиеся XML-теги, на которых `go vet` сообщает ошибки, поэтому копирование структур без сверки недопустимо.

Собственная библиотека находится в [`../python-epgu/`](../python-epgu/), использует `src` layout, типы, optional CryptoPro/XML dependencies, тесты, wheel/sdist и CI. CryptoPro/`pycades` не входит в публичный Python-дистрибутив и подключается отдельно в соответствии с лицензией поставщика.

## Блокеры публичной публикации

### P0 - обязательно до push/tag/release

1. Корневой и backend `.env` удалены из текущего индекса, но присутствуют в истории. Нужно считать все когда-либо находившиеся там API-key/PIN/токены скомпрометированными: отозвать или сменить их, переписать всю публикуемую историю согласованным `git filter-repo`/BFG-процессом и проверить свежий клон. Значения секретов в отчёте намеренно не приводятся.
2. `api-gosuslugi-backend/linux-amd64_deb.tgz` удалён из текущего индекса, но присутствует в истории. Это архив проприетарного CryptoPro CSP: его нужно убрать из истории либо документально подтвердить право на публичное распространение. `.gitignore` защищает будущие добавления.

### P1 - перед объявлением production-ready

1. Прогнать три доступных профиля Госключа в официальном тестовом контуре с выданными организации правами, ГОСТ TLS, реальными тестовыми сертификатами и безопасными синтетическими данными; отдельно завершить типизированную форму и fail-closed валидацию `60010153`, прежде чем проверять его в авторизованном контуре.
2. Зафиксировать golden ZIP для каждого capability: точные имена файлов, detached CAdES для каждого требуемого файла, namespace, лимиты и ответы ЕПГУ.
3. Официальные DOCX/PDF и дословно извлечённые XML/XSD исключены из Git из-за отсутствия явного разрешения на перераспространение. Публичный release хранит скрипт, URL, метаданные и SHA-256; полный snapshot скачивается локально с официального портала.
4. Опубликовать сначала TestPyPI, установить wheel в чистую среду поддерживаемых Python-версий и проверить импорт, metadata, extras, README links и отсутствие секретов/бинарников в wheel/sdist.
5. После переписывания истории убедиться, что добавленный CI hygiene gate и проверка содержимого release-артефактов проходят в свежем клоне.

```bash
python scripts/sync_api_for_gu_docs.py --check

cd python-epgu
python -m pytest
```
