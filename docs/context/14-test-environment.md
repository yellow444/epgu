# 14 - Тестовая среда ЕСИА (ТЕСИА)

Выжимка из инструкции Оператора «Инструкция по работе с тестовой средой 1.10»
(ЕСИА, 2024). Оригинал лежит рядом:
[`Instrukciya_po_rabote_s_testovoy_sredoy_1_10.pdf`](../Instrukciya_po_rabote_s_testovoy_sredoy_1_10.pdf),
пришёл письмом по запросу SCR#6451421 20 августа 2026 года. Здесь только то,
что нужно нашему стенду, и то, на чём легко обжечься.

Обратите внимание: адрес ЕПГУ тестовой среды из инструкции
(`pgu-uat-fed`) не совпадает с тем, что используем мы для API
(`svcdev-gostapi.test.gosuslugi.ru`). Первый нужен человеку в браузере,
второй машине для вызовов API, и это разные вещи.

## Три предупреждения, из-за которых теряют дни

1. Работать с тестовой средой только в режиме инкогнито или в отдельном
   браузере. Куки и кэш тестовой и боевой сред конфликтуют.
2. Организация «Тестовое ведомство» общая для всех участников тестирования.
   Редактировать чужие информационные системы, удалять и загружать чужие
   сертификаты и менять данные тестовых учётных записей запрещено.
3. Самая частая ошибка интеграции по версии Оператора это расхождение
   системного времени. Больше минуты расхождения с точным временем ломает
   взаимодействие с ЕСИА. Проверяйте NTP на машине со стендом.

## Табличные учётные записи

В инструкции приведён набор готовых учётных записей вида
`EsiaTestNNN@yandex.ru` с одним паролем и СНИЛС по шаблону. Менять их нельзя,
они общие. Есть подтверждённые физлица, сотрудники ЮЛ, ИП и сотрудники ОГВ,
одна запись с доступом в технологический портал. Для проверки подписи в
инструкции лежат тестовые ключевые контейнеры с ПИН, вложенные прямо в
документ.

Про эти вложения отдельно: в присланном нам PDF значки контейнеров видны, а
самих файлов внутри нет. Так бывает после печати документа Word в PDF. Наш
разбор вложений это замечает и советует запросить исходный документ, см.
[04-api-reference.md](04-api-reference.md).

## Что важно про учётные записи

- СНИЛС и ИНН в тестовой среде выдаются случайными, запросы в ведомства
  ТЕСИА не выполняет. Нужны конкретные значения - только через поддержку.
- Подтверждение почтовым кодом для части услуг считается недостаточным, для
  тестирования заявлений нужна учётная запись, подтверждённая электронной
  подписью.
- Учётную запись организации создаёт руководитель своей КЭП. Данные
  подтягиваются неправильные (`ОРГАНИЗАЦИЯ 000000000`, чужие ИНН и КПП),
  исправляются заявкой в поддержку ЕСИА по шаблону из инструкции: полное и
  краткое наименование, ОГРН, ИНН, КПП, тип, СНИЛС сотрудника и его роль.
- С неверными ИНН и КПП не работает раздел «Доверенности».

## Как теперь получаем сертификат

Раньше сертификат просили письмом в поддержку и ждали ответа сутками.
Инструкция предлагает другой путь: выпустить его самим в тестовом
удостоверяющем центре КриптоПро, `testca2012.cryptopro.ru/ui/`. Стенд умеет
собрать запрос сам, шаг «Сертификат» мастера, блок «Получить тестовый
сертификат»:

1. Имя владельца собирается из реквизитов организации: наименование,
   должность, почта, ИНН, ОГРН, СНИЛС, фамилия и имя отдельными полями. Это
   тот же набор, что стоит в сертификате, который тестовый УЦ РТК выдал нам
   в прошлый раз, и его видно и можно поправить до выпуска.
2. Кнопка «Создать запрос» делает ключевой контейнер и файл PKCS#10. Ключ
   остаётся на стенде, наружу уходит только открытая часть внутри запроса.
   Генерация занимает около минуты: аппаратного датчика случайных чисел в
   контейнере нет, энтропия набирается программно.
3. Запрос копируется кнопкой или скачивается файлом `.req` и подаётся в
   удостоверяющий центр.
4. Выпущенный `.cer` приносится обратно кнопкой загрузки, ставится в
   хранилище и связывается с тем же контейнером.
5. Тот же файл загружается в карточку ИС на технологическом портале ЕСИА.

Письмо в поддержку остаётся запасным путём, шаблон никуда не делся.

## Сертификат информационной системы

Сертификат ИС загружается в технологическом портале ЕСИА: вход под тестовой
учётной записью с правом доступа, поиск своей системы по мнемонике, кнопка
«Сертификаты», «Загрузить сертификат». Там же правятся данные системы.

Для нас это означает: файл `.cer`, который мы получаем от тестового
удостоверяющего центра, нужен в двух местах. В хранилище КриптоПро на стенде
(мастер настройки, шаг «Сертификат») и в карточке ИС на технологическом
портале. Одно другое не заменяет.
