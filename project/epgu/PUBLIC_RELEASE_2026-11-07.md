# Публичная часть: гайд, карточка, HTTP и MCP

Этот срез подходит для воспроизводимой инженерной демонстрации. Он не является
подтверждением полного подключения к Госуслугам или разрешением оператора.

## Запуск бесплатного интерфейса

Из корня Git-репозитория, PowerShell, Node.js 24:

```powershell
cd project/api-gosuslugi-client
npm ci
$env:HOST='127.0.0.1'
npm start
```

Откройте `http://127.0.0.1:3000/#connection`. Сервер установки и учётная запись
для этих разделов не нужны. Без backend гайд показывает встроенную копию
знаний. Адрес выбранного узла схемы можно открыть отдельно.

| Раздел | Что делает | Чего результат не доказывает |
| --- | --- | --- |
| `#guide` | Десять маршрутов: API ЕПГУ, ЕСИА, СМЭВ, подпись, MAX и цифровой рубль; источники со статусами и датами | Актуальность каждого внешнего сайта и наличие рабочего коннектора |
| `#manual` | Порядок ручного подключения, ссылки TEST/PROD, пустые поля и подготовка письма | Отправку обращения, регистрацию ИС или выданный доступ |
| `#connection` | Три задачи TEST, 12 enum-признаков и 37 правил; объяснение шага и ссылки | Проверку кабинета, сертификата, полномочия или успешный вызов API |

Карточка считает локально и не сохраняет отметки между перезагрузками. На узком
экране результат находится перед формой; на широком рядом с ней. Справочные
ссылки открываются отдельно и не передают отметки. Учебный пример остаётся
учебным после редактирования; «Начать свой разбор» очищает его значения.

## Тот же расчёт по HTTP и MCP

Backend устанавливается по `api-gosuslugi-backend/requirements.txt`, включая
локальный пакет `knowledge`. См. инструкции backend. Для примера ниже используется
обычный loopback-адрес установки `http://127.0.0.1:55000`.

```powershell
$body = '{"goal":"obtain_api_key","facts":{"same_context":"reported_yes","application_submitted":"reported_yes","application_received":"reported_yes"}}'
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:55000/v1/knowledge/connection-card/evaluate' -ContentType 'application/json' -Body $body
```

В ответе `basis=caller_reported`, правило `application_pending`. Приём анкеты
не становится выданным полномочием или полученным ключом. POST передаёт
enum-отметки вашему HTTP-серверу; интерфейс, в отличие от него, считает локально.
Идентификаторы, свободный текст, ключи и файлы контракт не принимает.

Для MCP из корня репозитория:

```powershell
python -m pip install -e ./project/knowledge -e ./project/mcp-server
python -m epgu_mcp --profile knowledge --no-extensions
```

Подключите этот stdio-процесс к своему MCP-клиенту. Инструмент
`knowledge_evaluate_connection_card` принимает тот же JSON, что HTTP-метод.
Штатный профиль `knowledge` содержит 11 справочных инструментов и не исполняет
внешние операции. Схемы, поиск, source_ids, данные ручного маршрута и
выход карточки общие с HTTP/UI. Подключение настоящей языковой модели не
требуется для воспроизведения этих проверок и этим релизом не заявляется.

## Инфраструктура рабочего раздела

В публичном ядре есть отдельно проверенные на mocks HTTP-клиенты и контракты
подготовки, предпросмотра, одобрения и исполнения плана. Ключ интеграции не
заменяет сессию человека; MCP не одобряет планы. Встроенных исполнителей
внешних операций нет: без зарегистрированного исполнителя prepare/execute
отказывают. Эта инфраструктура нужна для расширений и сама по себе не
превращает справочную карточку в автоматизацию Госуслуг.

Приватные дополнения, работа с несколькими организациями, браузерное расширение,
захват уведомлений и установленный Runtime в эту поставку не входят. Публичная
установка рассчитана на одного доверенного оператора; открывать её рабочие
методы в Интернет как готовый сервис нельзя.

## О чём можно писать в статье

Можно показать общую модель знаний, кликабельные схемы, три учебных сценария,
одинаковый расчёт в UI/HTTP/MCP и отрицательные проверки на mocks. Указать
границы между входом, подписью, доверием УЦ, полномочием ИС и API-Key.

Нельзя объявлять доказанными полный цикл в TEST/PROD, выдачу доступа любому
разработчику, работу MAX/цифрового рубля как готовых коннекторов или поддержку
каждой услуги каталога. Пять доступных профилей в локальном реестре — это
проверка реализации, а не пять подтверждённых оператором интеграций.

Даты проверки источников видны в гайде. Этот релиз не означает, что документы
и внешние кабинеты были заново проверены в день публикации. Локальные тесты,
сборка и визуальный просмотр не подменяют внешнюю приёмку.
