# 09 — Открытые вопросы и риски

Состояние проверено 2026-08-12. Закрытые пункты отсюда удаляются, а не перечёркиваются.

## 1. История Git требует очистки перед публикацией

В текущем индексе `.env` и `api-gosuslugi-backend/.env` не отслеживаются; отслеживаемый `.env.example` содержит только плейсхолдеры. Плейсхолдеры сами по себе не являются секретами, а локальные ignored-файлы нельзя добавлять в релизный артефакт.

При этом прежние ревизии содержали `.env`. По состоянию одного текущего файла нельзя доказать, что во всей истории никогда не было рабочего API-ключа, PIN-кода или другого секрета. До публичного релиза необходимо:

1. отозвать или сменить все значения, которые когда-либо использовались в исторических `.env`;
2. переписать историю, удалив `.env` и иные чувствительные артефакты из всех refs;
3. просканировать секреты в свежем клоне уже очищенного репозитория;
4. только после этого создавать тег и release artifacts.

## 2. Проприетарный архив КриптоПро есть в истории

Публичный backend Dockerfile теперь собирает Python slim core без CSP и `pycades`; архив дистрибутива не отслеживается текущим индексом. Однако прежние коммиты содержали `api-gosuslugi-backend/linux-amd64_deb.tgz`. До публикации нужно удалить blob из всей истории и refs, проверить очищенный клон и убедиться, что ни source distribution, ни Docker build context, ни release archive его не включают.

Реальная подпись остаётся функцией отдельного закрытого runtime с законно полученной лицензией. Сертификаты, закрытые ключи, PIN и CSP нельзя добавлять в public image.

## 3. Backend остаётся однопользовательским

Compose безопаснее прежней конфигурации: оба host-порта связаны только с `127.0.0.1`, CORS по умолчанию ограничен `http://localhost:50080`, внешний debug-порт отсутствует. Но `ACCESS_TKN_ESIA` и выбранный сертификат остаются глобальными переменными процесса, а собственной пользовательской аутентификации, per-session isolation, rate-limit и аудит-журнала нет.

Поддерживаемый сейчас сценарий — один доверенный оператор на локальной машине. Перед сетевым или многопользовательским развёртыванием нужны модель аутентификации, изоляция токенов/сертификатов, TLS, CSRF/CORS policy, rate-limit и аудит операций.

## 4. 18 контрактов пока только справочные

Реестр содержит 21 профиль, но исполняются только три профиля Госключа: `10000000374` (только УНЭП), `60025907` и `60080470`. Остальные 18 остаются видимыми, но fail-closed заблокированными. Для каждого нужны непротиворечивые официальные XML/XSD, golden-тесты и проверка в соответствующем контуре. У ФССП `60010153` схема и транспорт каталогизированы, но XML демонстрационный: до включения нужны типизированная форма, fail-closed проверка placeholder/полей и приёмка в авторизованном контуре. Отдельно не разрешены УКЭП-вариант `10000000374` и расшифрование `60079416`.

## 5. Нет end-to-end проверки с выданным сертификатом

Автотесты проверяют SDK, backend и frontend; точные текущие числа публикует CI. Они не заменяют реальную подпись и отправку. Нужны тестовые API-ключ, сертификат организации и лицензированный CSP/`pycades`, чтобы проверить получение токена, detached CAdES и каждый исполняемый контракт в официальном тестовом контуре. Порядок доступа описан в [`08-access-and-certificates.md`](08-access-and-certificates.md).

## 6. Публикация Python-пакета не выполнена

Wheel/sdist собираются и проходят проверку, но `twine upload` не выполнялся. До загрузки нужно завершить очистку истории, проверить метаданные из чистого клона и выбрать TestPyPI/PyPI workflow. См. [`07-licensing-and-publication.md`](07-licensing-and-publication.md).

## 7. Legacy CRA остаётся долгом build-среды

`npm audit --omit=dev --audit-level=high` сообщает 0 production-уязвимостей, а Node.js и devDependencies не входят в финальный nginx-образ. Полный audit всё ещё показывает 57 advisories в legacy Create React App build/dev-дереве. Не применять `npm audit fix --force`: долг закрывается отдельной миграцией с CRA и повторной проверкой 20 frontend-тестов, lint и production build.
