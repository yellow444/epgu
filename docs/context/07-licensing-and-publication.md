# 07 - Лицензия и публикация библиотеки

## Что выбрано и почему

До 2026-06-28 репозиторий был под MIT. Цель владельца: остаться настоящим open
source, сохранить обязательную атрибуцию и иметь возможность продавать
коммерческую версию, не давая при этом другим бесплатно сделать закрытый
платный форк.

Выбрано двойное лицензирование:

- **AGPL-3.0-or-later** для всех. Главный рычаг здесь раздел 13: производные
  обязаны раскрывать исходники, в том числе при работе по сети (SaaS).
- **Коммерческая лицензия** для тех, кому copyleft не подходит. Условия и
  контакт в [`python-epgu/COMMERCIAL-LICENSE.md`](../../python-epgu/COMMERCIAL-LICENSE.md).

Владелец кода один, поэтому продавать закрытые лицензии он вправе при любой
открытой лицензии: она ограничивает других, а не автора.

Что лежит в репозитории:

- `LICENSE` в корне и в `python-epgu/` - канонический текст AGPL-3.0.
- `python-epgu/NOTICE` - копирайт и атрибуция go-api-epgu (MIT).
- SPDX-заголовок `# SPDX-License-Identifier: AGPL-3.0-or-later` во всех
  исходниках пакета.
- `pyproject.toml`: `license = "AGPL-3.0-or-later"`, соответствующий classifier,
  `NOTICE` и `COMMERCIAL-LICENSE.md` едут в sdist.

## Два следствия на будущее

1. **Единоличное владение кодом надо сохранять.** Если появятся контрибьюторы,
   с них нужен CLA (передача или широкая лицензия прав), иначе их вклад нельзя
   будет продавать под коммерческой лицензией.
2. **Выпущенная версия остаётся под AGPL навсегда.** Форкать её смогут всегда.
   Менять условия можно только для будущих версий.

Это не юридическая консультация, для коммерческой стратегии стоит свериться с
юристом.

Порядок публикации, когда дойдут руки:

```bash
cd python-epgu
python -m build
python -m twine upload --repository testpypi dist/*
python -m twine upload dist/*
```

Нужен токен PyPI (`__token__` и значение вида `pypi-...`) в `~/.pypirc` или в
переменных окружения.
