# Статистика репозитория

Бейджи берут **реальные просмотры и клонирования репозитория из GitHub Traffic API**, а не считают загрузки картинки README. Отображаются последние 14 дней по данным GitHub, не показатели за всё время и не число пользователей системы. Дата снимка включена в каждый бейдж: без обновления файла он не становится «живым» счётчиком.

Полный датированный снимок: [`snapshot.json`](./snapshot.json). `uniques` взяты из сводного ответа GitHub, а не получены сложением уникальных посетителей по дням. Первый и последний возвращённые дни хранятся отдельно; GitHub использует UTC.

Публичные Shields endpoints: [`views.json`](./views.json) и [`clones.json`](./clones.json). Секретов, сведений о посетителях, источниках переходов и популярных путях в них нет.

## Обновление

Из каталога `project/`:

```powershell
python scripts/update_repository_traffic.py
git diff -- docs/metrics/
```

Нужен существующий `GH_TOKEN` (либо `GITHUB_TOKEN`) в окружении с доступом к traffic API. Для fine-grained token достаточно выбрать **только этот репозиторий** и `Administration: read`. Не вставляйте токен в README, URL бейджа, аргументы команд или Git. Скрипт его не сохраняет и не меняет настройки репозитория. Обновлённые JSON нужно отдельно опубликовать обычным коммитом.

Сначала читаются и проверяются оба ответа API. При ошибке API, отсутствии токена или некорректном ответе прежние файлы остаются без изменений; нулевые показатели не подставляются вместо ошибки. Автоматический workflow и расписание пока не настроены. Для автоматизации нужно отдельно согласовать хранение токена и права публикации; это не требует передавать токен Shields.io.

Источники: [GitHub Traffic API](https://docs.github.com/en/rest/metrics/traffic), [доступ и период статистики](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository), [Shields Endpoint](https://shields.io/badges/endpoint-badge).
