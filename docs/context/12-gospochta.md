# 12 - Госпочта организации: официальный API ГЭПС

## Короткий вывод

Госпочту (ГЭПС) в личном кабинете организации можно читать **по официальному
API ЕПГУ**, через тот же маркер доступа и тот же ГОСТ TLS хост, которыми мы уже
пользуемся. Браузерный робот с Selenium для этого не нужен.

Документ лежит у нас в снимке каталога:
`docs/api_for_gu/source/Specifikaciya_API_GEPS_v1.0.docx`, «Спецификация API
ГЭПС. Приложение "Получение уведомлений Госпочты и Новости"», версия 1.0 от
29.01.2026. В каталоге это `protocol-specification`, SHA-256 записан в
[`catalog.json`](../api_for_gu/catalog.json).

## Четыре метода ГЭПС

Все идут через прокси API ЕПГУ, то есть с маркером доступа организации.
Хост тестовой среды из примеров спецификации: `svcdev-gostapi.test.gosuslugi.ru`.

| Шаг | Метод |
| --- | --- |
| 1. Заказать список | `POST /api/gusmev/proxy/geps-api-ext/api/messages/v1/search` |
| 2. Забрать список | `GET /api/gusmev/proxy/geps-api-ext/api/messages/v1/search/{searchTaskUuid}` |
| 3. Карточка уведомления | `GET .../api/messages/v1/message/{threadUuid}/{messageUuid}` |
| 4. Вложение или подпись | `GET .../api/messages/v1/attachment/{messageUuid}/{attachmentUuid}/{file\|sig}` |

Заказ списка: `startDateTime`, `endDateTime`, `statusFilter` (`ANY`, `READ`,
`UNREAD`). В ответ `searchTaskUuid`.

Список: `searchTaskStatus` (`SEARCH`, `PROCESSING`, `COMPLETED`, `ERROR`) и
`messageList` с полями `threadUuid`, `messageUuid`, `feedTitle` (отправитель),
`feedSubtitle` (тема), `isRead`, `createDate`.

Вложения в карточке: `attachmentUuid`, `fileName`, `fileSize`, `mimeType`,
`signed` (есть ли отсоединённая подпись), `statusMnemonic` и описание статуса.

## Ограничения, которые определяют архитектуру

- Диапазон поиска не больше **суток**, глубина не больше **30 дней**.
- **5 запросов на формирование списка в день** и **15 запросов на получение
  готового списка в день**. Карточки и вложения без лимита по количеству
  (78 и 155 запросов в секунду).
- Список готовится асинхронно, забирать рекомендуется **через час**, живёт
  **7 дней**.
- Нужна роль **«Руководитель организации» или «Администратор»**, иначе 403.
- Вызов равнозначен входу на портал: по ряду НПА уведомление считается
  врученным с момента входа. Постановление Правительства № 606 от 29.06.2016
  (извещения ФССП) и № 947 от 19.06.2021 (постановления по административным
  делам) прямо на это опираются. То есть **читать почту нельзя «на всякий
  случай»**: чтение запускает сроки.

Из лимитов следует режим работы: один заказ списка в сутки на сутки, забор
результата через час, дальше карточки и вложения без ограничений. Никакого
опроса каждые пять минут.

## Браузерный сбор

До появления API ГЭПС уведомления забирали через браузер: Selenium, вход по
ЭЦП, листание ленты, печать страниц в PDF. Этот путь остаётся запасным для
того, чего в API нет, и для организаций без доступа к API ЕПГУ.

Здесь его нет намеренно. Эта часть развивается отдельно и в приватном
репозитории; локальные заметки лежат в `private/`, каталог закрыт в
`.gitignore`. В публичный репозиторий из неё ничего не переносим.

Что из того опыта пригодилось здесь:

- Формат результата `Letters/Letter` (дата, отправитель, тема, текст,
  ссылка, тип документа, список файлов). Под него уже пишут интеграции,
  поэтому наш ответ по ГЭПС имеет смысл уметь отдавать и в таком виде.
- Модель работы: заявка с идентификатором, асинхронный воркер, результат
  файлом плюс папка вложений. Она хорошо ложится на лимиты ГЭПС.

## Роли: кем может быть обычное ООО

В регламенте подключения к API Госуслуг ролей ровно две, и «поставщика» среди
них нет:

- **Организация-вендор** - разработчик информационной системы.
- **Организация-потребитель** - организация, выполняющая запрос к API,
  используя ИС. Там же прямо сказано: вендор и потребитель могут быть одним и
  тем же лицом.

Обычное ООО без властных полномочий - это **вендор и потребитель
одновременно**: сами написали ИС, сами ею пользуемся. В заявке на доступ есть
параметр «Владелец ИС является организацией-потребителем» со значением «Да».
Если планируется работать в продуктивной среде для сторонних потребителей,
регистрируется ещё и тестовая организация-потребитель.

Слово «поставщик» относится к другой системе - к СМЭВ, где поставщик сведений
это ведомство или организация, за которой сведения закреплены нормативным
актом. Стать поставщиком по своему желанию нельзя, для этого нужны полномочия
или закреплённая за организацией функция. Поэтому наш реалистичный статус -
потребитель, а услуги мы подаём от лица своей организации либо от лица
пользователя с его согласия.

## Приставы: что реально доступно

В снимке каталога уже есть четыре услуги ФССП, все в статусе `reference`:

| Код | Услуга |
| --- | --- |
| `60010153` | Предоставление информации о наличии исполнительного производства онлайн |
| `10000000352` | Предоставление информации о ходе исполнительного производства онлайн |
| `10000000367` | Подача заявлений, ходатайств, объяснений, отводов и жалоб по исполнительному производству |
| `10000000396` | Информация об исполнительных производствах для снятия ограничений на выезд |

Спецификации на них лежат локально в `docs/api_for_gu/source/`. Для
`60010153` в проекте уже есть `req.xml` и тесты транспорта, статус держится
`reference` до тех пор, пока форма заявителя не научится отбивать
демонстрационные данные.

Вторая половина работы с приставами - входящая: извещения ФССП приходят именно
в Госпочту, и по постановлению № 606 они считаются доставленными с момента
входа на портал. То есть чтение ГЭПС и подача по `10000000367` вместе дают
замкнутый цикл: увидели извещение, ответили ходатайством или жалобой.

## План

1. Клиент ГЭПС в `python-epgu` и четыре метода в backend поверх существующего
   маркера доступа. Проверяемо на тестовом контуре без токена и браузера.
2. Хранение: заявка с идентификатором, состояние задачи, список, карточки,
   вложения на томе. Планировщик, который соблюдает лимиты сам.
3. Отдача наружу: отдельный процесс по образцу приёмника, с проверками из
   [`inbound_guard`](../../api-gosuslugi-backend/inbound_guard.py), форматы
   JSON и `Letters/Letter` для совместимости с чужими интеграциями.
4. Браузерный сбор - отдельно и в приватном репозитории, сюда не едет.
