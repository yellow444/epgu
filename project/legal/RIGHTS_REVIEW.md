# Проверка происхождения кода и прав

Дата: 27 ноября 2026 года. Базовый публичный commit: `5d278466ac8f69eb051015c1ee964c2a0a84b72e`. Проверка относится к backend и UI текущей публичной поставки. Runtime, действующие ИС, приватные дополнения и контейнеры в нее не входят.

## Вывод для коммерческой альтернативы

Владелец [подтвердил](OWNER_CONFIRMATION.md) права на собственный код с исключением библиотек, шаблонов и данных Госуслуг. Доступная история текущих исходников соответствует этому подтверждению. Выявленный сторонний PR касается старого деплоя, отсутствующего в проверяемой публичной поставке. На этой основе подготовлен отдельный коммерческий вариант для собственных авторских частей, с сохранением прав сторонних компонентов.

Git и метаданные зависимостей не являются абсолютной гарантией отсутствия чужих прав. Новые вклады и конкретный архив поставки нужно проверять отдельно. Само указание коммерческой альтернативы не отменяет AGPL или сторонние лицензии для кода, на который такого права нет.

## Авторство и внешний PR

Проверены 164 отслеживаемых файла backend/UI и построчное авторство 116 исходных файлов. В этих исходниках доступный blame указывает на учетную запись владельца проекта. Это сведения о коммитах, а не самостоятельное доказательство авторства каждой строки или отсутствия прав работодателя.

В доступной Git-истории два автора. Кроме локальной истории проверен исходный [PR #2 от introquest](https://github.com/yellow444/epgu/pull/2), принятый 10 апреля 2025 года. Он содержал:

| Файл прежней структуры | Изменение |
| --- | --- |
| api-gosuslugi-backend/Dockerfile | Python 3.12, многоступенчатая сборка, непривилегированный пользователь app, установка КриптоПро и pycades |
| api-gosuslugi-backend/certs/entrypoint.sh | Удаление двух chown и изменение завершающей строки запуска |

| api-gosuslugi-backend/pycades.zip | Удаление архива, загрузка pycades при сборке |

Текущая публичная поставка не содержит этих Dockerfile, entrypoint, Compose и архивов. PR не изменял обработчики API и React-компоненты. Коммерческий перечень не включает старую контейнеризацию. Если она используется в другой поставке, вывод о текущем публичном backend/UI к ней не переносится.

Локальная история ранее очищалась, поэтому одной сводки git shortlog было бы недостаточно. Удаление автора из .mailmap или переписывание истории не прекращает права на его вклад. Для этого аудита история не переписывалась и авторы не удалялись.

## Шаблоны, данные и исключения

Три изображения public/favicon.ico, public/logo192.png и public/logo512.png побайтно совпали с Create React App. Они и используемые части шаблона сохраняют MIT; соответствующий текст включен в уведомления UI. Права на названия и логотипы не передаются как наши коммерческие права.

Сертификаты в certs/public сохраняют происхождение от УЦ. Документы и данные Госуслуг, чужие XSD и другие официальные материалы не перелицензируются от нашего имени. Встроенные копии knowledge сохраняют Apache-2.0. Даже когда файл содержит наш код вместе со сторонними частями, коммерческое разрешение относится только к нашим авторским частям.

Подготовительный [перечень](commercial-scope.json) содержит 146 записей собственных частей и 18 исключений исходного среза. Хеши идентифицируют байты перечисленных файлов, включая окончания строк. Базовый commit определяет исходный срез кода; документы и перечень подготовки добавлены позднее. Перед конкретной поставкой нужен ее актуальный состав и SHA-256 архива.

## Зависимости backend

Проверен фактически установленный runtime из 28 Python-пакетов. Версии прямых зависимостей совпали с requirements.txt. Собраны тексты LICENSE/NOTICE из установленных пакетов, включая отдельные уведомления lxml и typing_extensions. [Перечень](backend-runtime-dependencies.json), [полные уведомления](../api-gosuslugi-backend/THIRD_PARTY_NOTICES.txt).

В runtime есть certifi под MPL-2.0. Эта библиотека не становится проприетарной по нашему соглашению. При распространении соблюдаются ее условия, включая доступность относящихся к ней исходников. Сохранен локальный снимок установленного certifi с исходниками и лицензией для проверки и подготовки поставки. Новые изменения MPL-файлов проверяются отдельно. Это не требует перелицензирования отдельных собственных файлов заказчика.

SDK и knowledge включаются как самостоятельные Apache-пакеты с собственными LICENSE/NOTICE. КриптоПро CSP и pycades не входят в проверенный Python runtime и коммерческие права на них не предоставляются.

## Зависимости UI

Проверено 114 runtime-записей package-lock.json. Установленные версии совпали с lock; заявленные лицензии этих записей: MIT, BSD-3-Clause, Apache-2.0, ISC и 0BSD. [Перечень с источниками уведомлений](ui-runtime-dependencies.json), [полные уведомления UI](../api-gosuslugi-client/public/licenses/third-party/NOTICES.txt).

У трех пакетов лицензия содержалась в README вместо отдельного LICENSE: agent-base, https-proxy-agent и is-mobile. Для @ant-design/icons-svg MIT-текст получен из официального upstream по gitHead опубликованной версии. Эти тексты включены в уведомления, отсутствие LICENSE в корне пакета не было выдано за отсутствие обязательств.

В dev-зависимостях есть axe-core под MPL-2.0 и caniuse-lite под CC-BY-4.0, а также варианты выбора лицензии. В старых метаданных exit и prelude-ls лицензия подтверждена текстом MIT, esprima содержит BSD-текст в заголовке исходника. Это инструменты разработки; данный аудит не объявляет node_modules или весь набор инструментов сборки проприетарными. При поставке таких инструментов их состав и условия учитываются отдельно.

Минифицированные .LICENSE.txt от сборщика сохраняются вместе с дополнительным перечнем уведомлений. Их нельзя удалять из коммерческого архива только потому, что есть наше соглашение.

## Перед выдачей коммерческой поставки

1. Зафиксировать commit, состав собственных файлов и хеши фактического архива. Обновить перечень, если код или зависимости изменились.
2. Проверить новые внешние вклады и сохранить явные разрешения, включая права работодателя, когда это применимо.
3. Приложить сторонние лицензии и уведомления. Для включенных MPL-компонентов обеспечить предусмотренную их лицензией доступность соответствующих исходников.
4. Отдельно проверить бинарные зависимости, системные пакеты, образ контейнера, шрифты и ресурсы, если они входят в конкретную поставку. Перечень метаданных Python/npm не заменяет полный SBOM такого образа.
5. Заполнить и согласовать [коммерческое соглашение](COMMERCIAL_LICENSE.md). Поддержка, гарантии и доступ оператора не возникают из самого шаблона.

Старые AGPL- и Apache-копии сохраняют ранее предоставленные права. Блокировок, проверки лицензионного сервера и передачи пользовательского кода в рамках этой подготовки не добавлено.
