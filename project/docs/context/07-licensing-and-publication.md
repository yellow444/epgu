# 07 - Лицензии и сборка пакетов

## Текущая схема

С версии epgu-api 0.4.0, epgu-knowledge 0.2.0 и epgu-mcp 0.2.0 эти три самостоятельных пакета используют Apache-2.0. Backend и веб-интерфейс сохраняют AGPL-3.0-or-later. Полная [карта лицензий](../../LICENSING.md) отделяет собственный код от импортированных материалов и сторонних зависимостей.

Встраивание Apache-пакетов в закрытые приложения не требует покупки отдельного разрешения. При распространении сохраняются применимые LICENSE и NOTICE. [Коммерческое сопровождение и дополнения](../../COMMERCIAL.md) согласуются отдельно.

Старые MIT- и AGPL-версии сохраняют прежние условия. История и теги не переписываются. Отдельные дополнительные права можно предоставлять только в отношении кода, на который у предоставляющего их лица есть соответствующие права. Согласие с лицензией компонента не является автоматически подписанным CLA.

## Что проверять при изменении лицензии

- Метаданные pyproject, SPDX в исходниках и LICENSE должны соответствовать друг другу.
- NOTICE сохраняет авторство и применимую атрибуцию, в том числе go-api-epgu в SDK.
- LICENSE и NOTICE должны присутствовать в wheel и sdist каждого пакета.
- MCP operations требует epgu-api начиная с 0.4.0, основной MCP требует epgu-knowledge начиная с 0.2.0.
- Встроенные JSON и схемы knowledge сохраняют Apache. Статическая сборка UI содержит их LICENSE и NOTICE, хотя приложение остается под AGPL.
- Официальные документы, чужие XSD, CryptoPro CSP и pycades не получают новую лицензию от нашего имени.

## Сборка

Из каталога соответствующего пакета в отдельном окружении:

```bash
python -m build
python -m twine check dist/*
```

После сборки установить новые wheel в чистое окружение и проверить версии через importlib.metadata, зависимость MCP operations от SDK и корректный запуск stdio. Полный mock-цикл HTTP/MCP описан в [инструкции публичной проверки](../../epgu/PUBLIC_SINGLE_ORG.md).

Версии меняются одновременно в pyproject.toml, модульном __version__ и changelog. Создание wheel не означает публикацию на PyPI. Эта смена условий подготовлена локально; загрузка пакетов выполняется только по отдельному поручению владельца. Учетные данные публикации не входят в Git.
