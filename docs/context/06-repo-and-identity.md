Рабочая копия: `F:\source\repos\yellow444\epgu`.
Единственный remote:

```

```

перенесено (в частности, каталог `docs/context`). Если она где-то появится
снова, это не рабочая копия.

Прежние remote `QuadYellow/epgu` и `origin-old` удалены, упоминания `knightmc` и
`QuadYellow` из файлов вычищены.

Локальный `git config` в этой папке выставлен на `Maksim <yellow444@gmail.com>`,
чтобы коммиты не уходили под другую подпись. Глобальный конфиг исправлен там же
2026-07-31.

## Авторы

В истории должно оставаться ровно два участника:

```
Maksim <yellow444@gmail.com>
Maksim Shatov <maksim@shatov.info>   (introquest)
```

Подпись со второго, рабочего аккаунта из истории убрана: это тот же человек, но
GitHub показывал его отдельным контрибьютором.
Соответствие прежних подписей каноничным зафиксировано в
[`.mailmap`](../../.mailmap), чтобы `git log`, `git shortlog` и сторонние
инструменты считали правильно.

Важно: GitHub привязывает коммит к аккаунту строго по email автора. Поэтому
переименование без смены email ничего не меняет, а смена email меняет всё.

### Кэш виджета Contributors

После переписывания истории виджет в сайдбаре репозитория продолжал показывать
трёх участников, тогда как REST API
(`GET https://api.github.com/repos/yellow444/epgu/contributors?anon=1`) и график
Insights показывали двоих. Прошло больше пяти суток, само не рассосалось.
Вывод: протух ровно один кэш, самообслуживанием не чинится, единственный путь -
обращение в GitHub Support с указанием расхождения между их же API и их же
виджетом. Обращение было подготовлено и отправлено 2026-08-05, результат в
проекте не зафиксирован.

Чего делать не стоит: удалять корпоративный email из рабочего аккаунта.
Коммитов с ним в репозитории уже нет, разрывать нечего, а если это
primary email или аккаунт состоит в организации работодателя с ограничением по
домену или SAML, удаление создаёт реальные проблемы ради строчки в сайдбаре.

## Правила по текстам и коммитам

Приняты в июне 2026 и действуют дальше:

- В коммитах и файлах репозитория нет упоминаний вспомогательных инструментов и
  их служебных каталогов.
- Тексты человеческие: дефис вместо длинного тире, `->` вместо стрелок, никаких
  эмодзи, галочек, значков и псевдографики.
- Файлы клиента (`api-gosuslugi-client/`) сохраняются в CRLF, иначе падает
  сборка CRA. Shell-скрипты - только LF, это закреплено в `.gitattributes`.
- Несвязанные правки не подбираются в коммит попутно: в рабочем дереве обычно
  лежит много незакоммиченного.
